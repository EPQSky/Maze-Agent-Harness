# 08 — 确定性门禁与评测缓存

**What to build:** 在任何候选版本进入隐藏评测、缓存或晋级前执行统一的构建、协议、隔离、资源和确定性门禁。完整评测只有在不同启动时间与调度扰动下至少三次结果逐字节一致后，才能通过内容身份复用。

**Blocked by:** 06 — 生成器配对评测；07 — 求解器配对评测

**Status:** ready-for-agent

- [ ] 统一候选门禁能区分构建失败、协议失败、非法输出、资源超限、非确定性和基础设施故障，并使用稳定枚举原因。
- [ ] 相同插件提交、输入、镜像、规则和资源策略在不同启动时间与调度扰动下至少运行三次，比赛事件和评分必须逐字节一致。
- [ ] 时间或进程内随机 API 影响输出时，候选关闭失败；系统界面和文档不宣称容器能够完全禁止这些 API。
- [ ] 缓存键覆盖引擎、协议、评分与规则摘要、双方提交、种子、镜像摘要和资源策略，只保存完整且通过确定性复检的结果。
- [ ] CPU 和墙钟遥测不属于权威缓存结果，缓存命中与重新执行产生相同评分和晋级判定。
- [ ] 基础设施故障最多重试两次后停止实验且不产生竞争结论，插件故障不得被误分类为基础设施故障。
