## 问题陈述

用户希望研究两个代码进化智能体如何在可控、公平且可审计的环境中持续改进两个真实的 DeepSeek Harness 插件：Generator Plugin 与 Solver Plugin。现有迷宫演示通常只能运行固定算法，无法观察智能体自主修改、验证、晋级和版本化 Harness 插件，也无法区分真正的插件进步、模型临场推理、评测泄漏、裁判篡改和基础设施故障。

用户还需要直接观察迷宫逐步生成和逐步求解，查看每代候选、评分与插件谱系，并能回放任意历史比赛。实验必须允许选择 DeepSeek Harness 已配置的其他模型，同时保证同一实验内双方配置公平、规则冻结、隐藏评测密封，且比赛结果能够精确重放。

## 解决方案

构建本机单用户的 Maze Arena。可信的进化编排器通过 DeepSeek Harness 分别运行生成进化智能体和求解进化智能体；两个智能体只在比赛之间修改各自完整的 DeepSeek Harness 原生插件包、测试和策略记录。正式比赛不调用大模型，而是在受限容器中启动不含模型适配器和 Agent Loop 的 Match Profile，通过最小协议适配层调用指定版本插件注册的能力。整个 Match Profile 子进程均视为不可信，只有 Arena Server 保存隐藏状态、验证输出并计算权威结果。

Maze Arena 对迷宫合法性、局部观察、资源预算、公开与隐藏配对评测、字典序评分和自动晋级拥有唯一权威。它把逻辑比赛事件持久化，并以同一事件流驱动 Web 直播、暂停、单步、倍速和历史回放。每个实验冻结模型配置档、规则和兼容性指纹，通过 SQLite 保存实验事实，通过独立 Git 谱系保存双方代码版本，并提供密封、克隆、延续和审计能力。

## 实现决策

- 项目采用 Node.js 22、TypeScript 和 pnpm 构建单体代码仓库，其中包含竞技场 Web 应用、竞技场服务端、共享契约、竞技场引擎、比赛配置档运行器、进化编排器、DeepSeek Harness 集成层、最小比赛协议适配插件，以及原生 Generator Plugin 和 Solver Plugin 基线包。
- 竞技场 Web 使用 React、Vite 和 Canvas；竞技场服务端使用 Fastify；默认测试运行器为 Vitest。
- 初始部署面向本机单用户。一个竞技场实例同时只允许一个实验运行，已保留实验仍可浏览和回放。
- 系统通过独立且精确锁定版本的集成适配层访问 DeepSeek Harness。生成器和求解器智能体分别使用隔离的 Harness 主目录与工作区。
- 每个实验配置一个模型配置档，而不是写死 DeepSeek 模型。配置档包含提供方、模型、可选推理与采样字段、输出与上下文预算、提供方专用选项及凭据引用。
- Harness 适配层负责验证提供方能力并拒绝不受支持的字段，不得静默丢弃用户要求的模型参数。
- 初始的对称实验类型要求双方使用相同模型配置档；本规格不包含单个实验内使用非对称模型配置的能力。
- 只有操作员监督的基线验收确认协议、沙箱、评测、持久化、回放和晋级行为均正常后，才能开始正式进化。
- Arena Server 及其竞技场引擎、持久化层和进化编排器属于可信组件。进化智能体、候选插件以及加载候选插件的整个 Match Profile 子进程均视为不可信，不能持有评分权威、未授权隐藏数据或可修改的历史记录。
- Generator Plugin 和 Solver Plugin 是两个完整的自进化产品。每个产品都是可安装的 DeepSeek Harness 包：清单声明 `dsh.bundle` 层，bundle 挂载插件入口，`apply(ctx)` 向比赛配置档注册且只注册一个角色专用能力。
- 候选验证允许智能体改进己方 bundle 和插件组合，但所有引用模块必须属于候选包，所有贡献项必须处于冻结的角色能力和安全策略之内。候选版本不得利用 bundle 注入任意 Harness 服务或替换可信比赛配置档条目。
- 进化智能体是由编排器使用固定角色提示、工作区、权限和工具配置的 DeepSeek Harness 会话，但其模型输出、工具行为和候选产物均按不可信输入验证。智能体与其目标插件之间不存在另一个可变的 Harness 进化插件。
- 初始阶段允许智能体修改完整的己方插件包，包括算法、内部结构、Harness 注册、测试、文档和策略日志条目；不得修改冻结的比赛配置档、最小协议适配插件、公共能力契约、依赖集合、Harness 核心、评测策略或对手插件。
- 每次候选尝试都使用新的 Harness 会话。智能体长期记忆由 `lineage/` 中不可变的逐次尝试策略计划，以及 SQLite 中由可信编排器生成并可按候选身份查询的结构化结果记录共同表示。
- 进化智能体只能获得己方代码、可信报告、公开轨迹、聚合历史反馈和经过净化的类型化诊断。由对手控制的标准错误、注释、自由文本、提示词、源码和推理过程均不得进入其上下文。
- 智能体工具包括限定范围的文件查看与编辑、搜索、命令行、测试、有界公开候选检查和候选提交。禁止访问网络、子智能体、隐藏评测和任意宿主路径。
- 模型提供方限流、连接或服务错误最多执行三次退避重试，随后暂停实验，且不消耗候选尝试次数或进化代。模型成功响应但产生无效插件候选版本时，记为进化失败。
- 每个实验创建两个不含远程地址的独立 Git 仓库，每个仓库保存一个完整且可安装的 DeepSeek Harness 插件包。不可变基线提交分别作为 Generator Plugin 和 Solver Plugin 谱系起点。
- 进化智能体不控制 Git。编排器负责校验允许修改的路径，并将所有候选版本及失败尝试保存为不可变谱系证据。冠军引用是指向提交的可信指针。
- 候选版本通过晋级后，编排器在该角色仓库中创建名为 `promotion/<experiment-id>/<role>/gNNNN` 的附注 Git 标签。编排器从不移动或删除该标签；标签消息记录实验身份、角色、代次、晋级提交、上一冠军、评分摘要和兼容性指纹。失败或平局的候选版本不创建晋级标签。
- 晋级状态和晋级标签创建共同组成一个可恢复的编排步骤。SQLite 同时保存预期标签名、标签对象标识、目标提交和元数据摘要；重启恢复和实验继续前必须校验这些值。缺失标签可根据可信预期记录幂等补建，冲突、移动、删除或元数据不一致均生成篡改审计事件并关闭失败。
- 可安装运行载荷最多包含 64 个源码文件且总计不超过 256 KiB，构建产物不得超过 2 MiB。测试和文档属于不进入构建产物的辅助工程资料，每个候选版本最多包含 128 个此类文件且总计不超过 2 MiB。`lineage/` 属于独立的只追加谱系资料，不计入运行载荷或辅助工程资料累计配额；每次候选尝试只能新增一份不超过 64 KiB 的策略计划，既有条目不可修改。可信评测结果由编排器存入 SQLite，不复制进插件运行载荷。初始实验类型不允许进化插件新增依赖或生成二进制文件。
- 正式插件执行发生在一次性 Docker 容器内，容器启动精确锁定版本的 DeepSeek Harness 比赛配置档。该配置档只加载最小比赛协议适配插件和一个精确提交版本的 Generator Plugin 或 Solver Plugin，不加载模型适配器、智能体循环、命令行、编辑器或无关工具；整个容器进程均属于不可信执行域。
- 最小比赛协议适配插件只负责把带版本的 JSON Lines 请求转交给已注册的原生能力，并返回单个候选输出，不持有完整迷宫、隐藏评测信息、评分状态或历史事实。Arena Server 拥有协议状态机、请求关联、局部观察生成、完整拓扑、规则验证、事件提交和评分的唯一权威。
- 插件以非 root 用户运行，无网络权限；可信挂载只读，并提供私有临时可写区域。每场比赛限制插件使用 128 MiB 内存、两秒 CPU 时间和 100 毫秒单次响应墙钟超时，同时应用冻结的源码与产物限制。资源耗时只用于硬上限和遥测，界面播放时间不计入任何比赛资源上限。
- 协议信封包含协议版本、请求标识、消息类型和经过模式验证的载荷。Arena Server 每次只发送角色完成当前动作所需的最小输入，并只接受一个不超过 16 KiB、与请求关联且通过严格模式和领域验证的输出；额外字节、额外输出、乱序输出、超限输出、协议污染和进程级干预均使候选关闭失败。标准错误仅用于诊断且绝不向对手暴露。
- Generator Plugin 接收网格规则和确定性的生成器种子，从全墙网格开始，输出唯一且单调的凿通操作，最后发出完成信号。
- Solver Plugin 初始化时不接收生成种子，随后重复接收局部观察并返回四向移动。公共能力契约不提供时间、随机、网络或完整拓扑，但 Node.js 进程内的时间与随机 API 无法仅靠容器完全禁止；因此所有正式评测都必须执行至少三次、跨启动时间与调度扰动的确定性复检，任何输出差异都使候选关闭失败且不得缓存或晋级。该机制用于检测而非证明候选版本在所有未运行输入上必然确定。
- 初始迷宫是 31×31 的正交单元格网格，入口为第 0 行第 0 列，出口为第 30 行第 30 列。任意单元格之间均必须可达；允许存在环路和死路。
- Solver Plugin 接收当前位置、开放的四向通路、入口与出口坐标、剩余步数和上一步动作结果，并自行维护已访问状态和地图。非法移动也消耗一次动作。
- 求解器移动预算为 1441 次动作。求解器在耗尽预算或违反硬门禁之前进入出口即为成功。
- Generator Plugin 基线使用随机化深度优先回溯算法，之后执行固定低概率的环路开通步骤。Solver Plugin 基线使用带显式回退的已发现地图深度优先探索算法。
- 比赛事件以单调递增的逻辑序号表示权威生成器和求解器动作。实验审计事件表示控制与生命周期事实，并可包含真实墙钟时间。
- SQLite 以 WAL 模式保存实验、进化代、候选版本、比赛、评分、审计事件、比赛事件、冠军身份和预期晋级标签的权威事实。两个 Git 仓库及其附注标签是插件内容、谱系和可直接寻址成功迭代的权威来源。
- WebSocket 只负责临时投递。重新连接时按照序号从 SQLite 读取已提交事件。原始比赛事件只能追加并保留其协议版本。
- 实时执行在资源允许范围内尽快运行，不为动画主动休眠。Web 播放层使用已持久化的比赛事件流独立完成缓冲、暂停、单步、跳转和变速。
- 每个进化代在任一智能体启动前冻结双方冠军版本。智能体调用可以顺序执行，但双方候选版本必须基于相同的冻结代次输入进行评测，并在两个判定都完成后才执行晋级。
- 构建、协议、确定性、合法性、沙箱和资源检查均为硬门禁。构建、协议和公开检查失败最多允许三次修复尝试。最终提交后只执行一次隐藏评测，且不得利用其结果在同一代修复。
- 每个角色获得八个固定公开评测案例和二十四个按代派生的隐藏评测案例。案例在排序后的活跃对手池上确定性轮转；不足六个不同对手时，各对手获得的案例数相差不超过一个；正好六个对手时，每个对手获得四个隐藏案例。
- 隐藏种子由密封的实验主秘密和代次身份派生。生成器种子只能提供给对应的 Generator Plugin；Solver Plugin 和进化智能体不能读取隐藏种子。
- 活跃对手池最多包含六个不同版本：基线、当前冠军、最近两个不同的历史冠军和两个历史强敌。缺失类别直接省略，案例在剩余且已排序的对手池上轮转。
- 历史强敌根据当前冠军最近一次完整历史评测结果选取；平局时按照提交哈希排序。每五代执行一次完整历史评测，替代有界对手池评测。
- 比较生成器候选版本时，候选版本和冠军版本使用相同案例种子分别生成迷宫，再由同一个冻结的 Solver Plugin 版本求解各自迷宫。
- 比较求解器候选版本时，冻结的 Generator Plugin 版本只生成一次迷宫快照，并将完全相同的快照分别提供给候选求解器和冠军求解器。
- 候选版本之间的比赛属于非评分展示局。双方同时晋级后可以直播该比赛，但它绝不改变任何一方的晋级判定。
- 公开评测首要指标不得退化。完整历史评测代还要求任何历史对手分组的首要指标均不得退化。
- Solver Plugin 晋级评分依次比较：成功求解案例数降序、额外动作总数升序、非法动作数升序。额外动作数等于成功案例的实际动作数减去可信最短路径长度。
- Generator Plugin 晋级评分依次比较：导致求解失败的案例数降序、成功求解案例中的额外动作总数降序、结构新颖度降序。
- 完全平局时不晋级。CPU 时间和墙钟时间仅用于资源硬上限、容量规划和非权威遥测，不参与评分、平局判定、缓存命中后的权威结果或跨实验比较。
- 竞技场引擎根据完整且已验证的拓扑计算最短路径。最短路径信息用于评分，但比赛期间绝不向 Solver Plugin 暴露。
- 每代的 32 个迷宫必须至少包含 29 个不同的规范拓扑哈希。结构新颖度使用凿通边集合相对已保留历史迷宫的 Jaccard 距离，并且只在合法性和对抗难度之后参与比较。
- 插件加载失败、能力注册缺失或重复、超时、内存溢出、非零退出、桥接协议格式错误、非法迷宫和非确定性都会拒绝候选版本，并禁止写入缓存。
- 竞技场、容器和存储故障最多重试两次。持续失败会将实验转为失败状态，不生成竞争结论，也不计入正常的无晋级代次。
- 评测缓存身份包含引擎版本、比赛配置档与桥接协议版本、评分与规则摘要、双方插件提交、种子、容器镜像摘要和资源策略。只有完整且通过重复确定性检查的评测才能缓存。
- Generator Plugin 和 Solver Plugin 候选版本独立晋级。如果双方均通过，则必须先为下一代完成双方冠军引用及角色本地晋级标签，再运行非评分的新冠军展示局。
- 失败候选版本仍保留在插件谱系中，但不能成为下一代起点。每个新进化代都从当前冠军版本开始。
- 一个实验最多运行 20 个正常进化代。连续五个正常完成的进化代双方均未晋级时结束实验；任一方晋级都会重置计数。基础设施故障不消耗进化代。
- 实验生命周期包含基线验收、就绪、运行中、已暂停、已完成、失败和已取消状态。状态转换必须先于副作用持久化。重启恢复从最后一个已提交原子阶段继续，且不得重复晋级。
- 播放暂停立即生效且只影响界面。实验暂停在当前原子单元结束后生效。终止会取消活动任务并使实验不可恢复；后续探索必须创建新实验。
- 运行中的实验不提供引导或聊天输入。操作员不能强制晋级、编辑评分、揭示隐藏比赛或更改冻结配置。
- Web 工作台包含竞技场、进化代、比赛、谱系、候选版本和审计视图。谱系视图把晋级标签显示为成功迭代里程碑。密封期间，隐藏评测只展示进度和聚合指标。
- 每个进化代指定一场公开展示局用于直播。其他评测在后台全速运行，仍可逐场回放，并报告聚合进度。
- 所有者可以使用公开种子，在任意保留的 Generator Plugin 和 Solver Plugin 版本之间创建非评分展示局。展示结果不得影响晋级、评分或对手选择。
- 每个隐藏评测套件都具有稳定的 `evaluationSuiteId`，所有复用该套件的实验共同属于一个密封组。只有密封组内所有实验均已停止后才能解封；解封操作对整个密封组不可逆生效，公开隐藏证据，并永久禁止组内所有现有实验及后续副本继续进化。
- 比较克隆复用原实验的基线、兼容性指纹、`evaluationSuiteId` 和密封评测套件，同时使用新的模型配置档和独立审计链。克隆必须继承密封组状态，不能复制出可独立解封或重新密封的套件。
- 延续分支从选定的冠军版本开始，使用新的隐藏主秘密，并可选择新的冻结配置。兼容性指纹发生变化时，延续分支不能与原实验直接比较。
- 兼容性指纹包括竞技场引擎、比赛配置档、竞技场桥接协议、评分、网格规格和资源策略版本。只有指纹完全相同的实验才能直接比较。
- 初始版本的实验数据只保留在本机工作目录中，不提供分享归档、脱敏导出、加密备份、跨实例导入或应用内实验删除能力。
- 系统分别报告各角色的进度、基线、插件谱系、交叉对战矩阵和最终对局，不跨生成器与求解器的不对称目标宣称单一全局胜者。
- 模型进化过程可审计，但不承诺在远程提供方变化后按位复现。对于冻结输入，原生插件在比赛配置档中的执行、比赛事件、投影和评分必须精确复现。

## 测试决策

- 主要测试接缝位于 Maze Arena 应用边界：提交冻结的实验定义、受控的进化智能体替身和比赛配置档替身，观察已持久化事件、投影状态、谱系变化、晋级标签、晋级判定和公共 API 响应。测试应断言外部可见行为，而不是内部类结构。
- 竞技场引擎属性测试生成广泛的迷宫和动作序列，并断言全局连通、固定起终点、合法凿通、可信最短路径、步数预算、非法动作计数、确定性评分和关闭失败验证。
- 比赛配置档协议契约测试运行黑盒 Harness 进程，验证插件加载、消息分帧、模式版本、请求关联、单一输出、16 KiB 帧上限、标准错误隔离、超时、进程退出和面向后续版本的拒绝行为；测试还必须让候选插件尝试污染标准输出、修改进程全局状态和干扰适配插件，并断言 Arena Server 拒绝异常输出且权威状态不受影响。
- 原生插件一致性测试通过 `dsh.bundle` 将每个包安装到隔离的 Harness 主目录，加载其比赛配置档，验证 `apply(ctx)` 注册且只注册一个角色能力，测试卸载清理，并拒绝缺失、重复、陈旧、包外或被禁止的配置档贡献项。配额测试分别计算可安装运行载荷、辅助工程资料和逐次新增的 `lineage/` 条目，断言文档与 `lineage/` 不进入构建产物，且累积谱系不会消耗运行载荷或辅助工程资料配额。
- 确定性测试使用相同插件提交、比赛配置档、镜像、规则和种子，在不同启动时间和调度扰动下至少运行三次，并在允许写入缓存或晋级前逐字节比较完整比赛事件序列与评分。
- 进化编排器集成测试使用可编程的假 Harness 适配层，覆盖新会话、受限输入、修复尝试、隐藏评测终局性、候选版本保留、同时晋级、停滞、令牌限制、提供方暂停和崩溃恢复。
- 晋级测试使用表驱动的候选与冠军评分元组，覆盖所有字典序边界、公开指标退化、完整历史分组退化和完全平局，并断言改变 CPU 或墙钟遥测不会改变晋级结论。
- 对手池测试覆盖无历史记录启动、不同对手少于六个、确定性轮转、提交哈希平局排序、历史强敌选择，以及第五代完整历史扩展。
- 持久化测试在每个实验状态转换处重启竞技场服务端，并断言候选版本、比赛、审计事件和晋级均不重复也不丢失。
- 晋级标签测试验证带实验和角色命名空间的附注标签名称与元数据，覆盖失败或平局时不存在标签、崩溃恢复的幂等性、双方同时晋级时标签相互独立，以及标签被删除、移动、重建为不同标签对象或指向错误提交时产生篡改审计并关闭失败。
- 事件投影测试只根据带版本的原始事件重建所有界面可见状态，并比较直播、重连和历史回放的投影结果。
- 沙箱测试尝试访问网络、写入宿主、修改依赖、生成超限产物、逃逸进程、读取随机设备及读取对手路径，并断言所有可强制禁止的行为都会关闭失败。系统时间和进程内随机 API 不宣称由容器完全禁止，而由确定性复检覆盖并在影响输出时关闭失败。
- 提示边界测试通过插件标准错误、源码注释、桥接协议字段和比赛数据注入对抗文本，并断言只有可信的类型化摘要能够进入进化智能体请求。
- 缓存测试验证完整身份键、仅确定性结果可写入、任一兼容性组成变化都会失效，以及公共查询不会暴露隐藏载荷。密封组测试覆盖克隆继承 `evaluationSuiteId`、组内尚有运行实验时拒绝解封、解封状态原子传播，以及组内所有实验和后续副本永久失去进化资格。
- Web 组件与端到端测试覆盖 Canvas 渲染、稳定布局、直播缓冲、播放/暂停/单步/跳转/变速控制、重连、进化代历史、候选差异、密封隐藏视图和展示局，并覆盖桌面与移动端视口。
- 模型配置档测试使用多个能力集合不同的假提供方，断言系统显式拒绝不受支持的推理、采样、上下文或提供方专用字段。
- 日常持续集成使用可编程假模型。真实的已配置提供方只在操作员监督的基线验收冒烟测试中调用，其非确定性响应文本不作为黄金断言。
- 由于仓库尚无实现测试，当前既有参考仅包括项目领域词汇表和 ADR 定义的契约。新增测试应保持在上述竞技场应用、进程协议、事件投影和安全边界上。

## 不在范围内

- 竞争智能体进化可信的进化提示词、权限、比赛配置档、竞技场桥接、公共能力契约、Harness 核心、评分规则、竞技场代码或评测协议。
- 正式迷宫生成或求解期间调用模型。
- 单个实验内使用非对称模型配置档。
- 多用户身份认证、授权、租户隔离、托管部署或分布式竞技场执行。
- 一个竞技场实例同时运行多个实验。
- PostgreSQL、外部消息队列、Kubernetes、微型虚拟机或远程 Harness 插件执行。
- 初始实现使用 TypeScript 以外的原生插件语言；尽管初始 Harness 插件均为 TypeScript 包，竞技场桥接协议仍保持与语言无关。
- 动态迷宫、加权地形、六边形网格、三维迷宫、仅基于视觉的求解，或 31×31 以外的迷宫尺寸。
- 实验运行期间的自由文本对手通信、源码共享、推理共享、人工引导或交互式辅导。
- 使用单一标量分数或全局胜者直接比较生成器与求解器目标。
- 模型提供方变更模型后精确复现远程模型的令牌输出。
- 分享归档、脱敏导出、加密备份、跨实例导入、自动清理或应用内删除实验。

## 补充说明

- 本规格于 2026-09-01 根据已确认的设计讨论、项目词汇表和已接受 ADR 汇总形成。
- DeepSeek Harness 被视为外部且快速演进的依赖，必须通过集成适配层精确锁定版本。
- 初始原生 Generator Plugin 和 Solver Plugin 基线刻意保持简单但正确；改进应来自智能体对完整 Harness 插件包的自主进化，而不是复杂的人工起始实现。
- 晋级标签表示一次成功的算法或插件迭代，并不表示向外部注册表发布软件包。发布插件包属于独立事项。
- “实时”是指流式传输并渲染已经提交的可观察动作，不表示按照真实墙钟速度执行，也不表示能够查看模型或算法的私有推理。
- 不同对手少于六个时，评测案例在实际且已排序的对手池上轮转，各对手分配数量相差不超过一个。达到六个对手时，每个对手获得二十四个隐藏案例中的四个。
- 本规格是上层规划交付物。实现顺序、垂直切片、验收标准和 `ready-for-agent` 状态由 `$to-tickets` 生成的任务票据定义。
