# 通过适配层精确锁定 DeepSeek Harness

项目通过独立的 dsh-integration 模块调用 npm 发布的官方 `@deepseek-ai/dsh`，并在操作员显式执行 `install` 时要求精确 SemVer、校验实际包名与版本、`dsh --version`、入口摘要和完整运行载荷摘要。当前正式验收锁定 `@deepseek-ai/dsh@0.1.2-rc.1`；拒绝 latest、dist-tag、版本范围以及 file、Git 或 URL 来源。安装成功后把包含平台可选依赖的完整依赖闭包物化为 Arena 私有的内容寻址冻结 runtime，`doctor`、模型同步、镜像构建、启动和实验只复用该 runtime，不再联网下载、自动升级，也不要求 Harness 源码或外部 `dsh`。正式适配器只通过 `dsh --profile sdk` 的 JSON-RPC stdio 协议工作。Harness 官方 `$DSH_HOME/settings.yaml` 是 provider、model、endpoint 与凭据环境变量名的唯一可变真源；Arena 只接受其严格 JSON 子集，显式同步后把 `settings.yaml`、公开 `catalog.json` 和私有 `model-export.json` 共同冻结到同一内容寻址只读 release，三者任一权限、链接、内容或身份漂移均关闭失败。官方 DeepSeek 成本倍率固定在版本化 adapter 中，自定义 pi-ai provider 必须使用 `pi-ai-configured-cost-v1` 策略身份及显式正倍率，settings 不能覆盖官方倍率。凭据引用统一为 `dsh-credential://NAME`，其中 `NAME` 必须符合 POSIX 环境变量名 `^[A-Za-z_][A-Za-z0-9_]*$`；凭据文件仅作为不读取内容且权限为所有者专用的私有文件描述符能力交给官方凭据插件，不挂载到 Agent 可见文件系统。

模型能力协议直接采用当前锁定官方 catalog 的推理枚举 `off`、`low`、`high`、`max`。旧 `medium` 不做静默映射，避免同一冻结配置在 Harness 升级前后产生不同含义；CLI、Server、Web 与导出解析器共同拒绝未声明值，Web 初始值始终取当前模型能力列表的首项。每次 `start` 都把已验证 release 的三个文件复制为该 Server 实例专属的 `0400` 文件和 `0500` 目录，记录聚合 SHA-256、文件路径与 release 身份。运行实例只读取该快照；原 `current` release 后续替换不影响实例，而实例快照任一文件的内容、权限、链接或同源关系变化都会在 catalog、smoke 或 evolve 调用前关闭失败。实验冻结配置、进程状态、备份清单、doctor 与金丝雀身份均携带同一模型发布摘要。

Arena 的 `allowedTools` 固定映射到官方 wire 工具 `read`、`read_image`、`write`、`edit`、`grep`、`glob`、`bash`；版本锁定 patch 禁用 web、jobs、skill、subagent、workflow、todo、goal、ralph、plan mode 和额外编辑器工具，关闭后台 Bash，并把并行工具调用限制为一，避免同一父 Session 之外产生未计量工作。官方 SDK usage 不提供账单金额，因此冻结 adapter 使用显式版本化的 `deepseek-official-cost-v1` Arena 成本单位，按 uncached input、cache read、output 分项与可信模型倍率累计整场父 Session 的全部模型调用并报告策略标识。成功与结构化失败响应都必须携带 `{tokens,cost,modelCalls}`；Arena 在启动 SDK 前按冻结模型整次调用上界预检剩余 token 和 cost，并在 SQLite 中按实验、代次、角色把父 Session 剩余的最多八次模型调用全部预留，收到可信 usage 后只归还未使用额度，无可信 usage 的崩溃保留预留，防止通过 repair 或进程重启绕过上限。达到任一预算即终止完整 SDK 进程组。adapter 同时对输入、单个 JSON-RPC 帧、累计 stdout、stderr、单事件、事件数量、累计事件字节、模型调用次数和会话空闲等待设置硬上限，超限关闭失败并终止进程组。未知模型、缺失 usage 分项、目录漂移、协议溢出或不一致均关闭失败，不把 Arena 成本值描述为提供方原生计费字段。Harness 升级必须由显式安装触发，并重新完成兼容性、成本策略、工具 wire 与保护基线验收，不能在正式实验中跟随浮动版本更新。

可信用量账本始终使用 `{tokens,cost,modelCalls}`。Baseline smoke 的成功和结构化失败用量进入基线记录、审计事件与金丝雀预算账本；evolve 的每次成功、失败和重试分别进入 Harness activity，角色完成后再把聚合值原子写入 checkpoint 与 runtime。金丝雀报告分别展示 smoke 和每个角色用量，并在 audit、checkpoint、runtime 与预算 ledger 之间逐项对账。`modelCallsUsed` 只表示已取得可信 usage 的实际调用，`modelCallsReserved` 单独表示父 Session 已用调用加上崩溃时保留的保守预留，不得把保守预留伪装成提供方实际用量。
